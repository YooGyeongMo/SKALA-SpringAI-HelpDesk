# Tradeoffs (결정 로그)

코드, 설정 주석, PR 본문에 근거가 있는 결정만 적었습니다.

| # | 상황 | 선택지 | 결정 | 비용 | 다시 볼 조건 |
|---|---|---|---|---|---|
| 1 | 여러 기능(RAG, 메모리, 안전, 계측)을 한 요청에 묶어야 함 | 서비스 코드에서 순서대로 호출 / Advisor 체인 | `ChatClient` 기본 Advisor 체인, 조립은 `AiConfig` 한곳 | 순서가 order 숫자에 숨어 있어 읽는 사람이 체인을 알아야 함 | Advisor가 10개를 넘거나 요청마다 체인이 달라질 때 |
| 2 | 민감어 차단과 이력 저장의 순서 | Memory 먼저 / SafeGuard 먼저 | SafeGuard(100)를 Memory(200)보다 바깥 | 차단 요청은 맥락에도 남지 않음 (의도된 것) | 차단 이력을 별도로 보관해야 할 때는 감사 로그로 |
| 3 | 사용자 신원을 도구에 전달 | 프롬프트에 포함 / `ToolContext` | `ToolContext` + 헤더 | 인증은 헤더라 위조 가능 | Spring Security 도입 시 헤더만 Principal로 |
| 4 | 주문 권한 검사 위치 | 조회 후 자바에서 비교 / 조회 조건에 포함 | `findOwned(orderId, userId)` | 저장소 메서드가 용도별로 늘어남 | JPA 전환 시 쿼리 메서드로 그대로 |
| 5 | 없는 주문과 남의 주문 응답 | 구분해서 안내 / 같은 문구 | 같은 문구 "해당 주문을 찾을 수 없습니다" | 사용자가 오타인지 권한 문제인지 모름 | 로그인 사용자 기준 "내 주문 목록" 제공 시 완화 |
| 6 | 환불, 교환 처리 | 도구로 즉시 처리 / 접수만, 승인은 사람 | 접수 도구만 제공, 승인은 REST API | 운영자 작업이 필수, 처리 지연 | 금액 기준 자동 승인 규칙이 생기면 서버 규칙으로 (모델 아님) |
| 7 | 도구 감사 | 각 도구에 로그 코드 / AOP | `@Around("@annotation(Tool)")` Aspect | AOP라 흐름이 코드에서 안 보임 | 도구가 외부 서비스로 분리되면 게이트웨이 로깅으로 |
| 8 | 출처 표기 | 모델에게 출처를 쓰게 함 / Advisor 컨텍스트 | `RETRIEVED_DOCUMENTS`에서 꺼내 `sources`로 | 검색은 됐지만 답에 안 쓴 문서도 출처로 붙음 | 문장 단위 인용이 필요해지면 |
| 9 | RAG 임계값 | 일반적인 0.62 / 실측 | 0.28 (관련 0.315~0.44, 무관 0.16~0.245) | 코퍼스가 바뀌면 다시 재야 함 | 문서 추가, 임베딩 모델 교체 시 `/chunks`로 재측정 |
| 10 | 청크 크기 | 작게 / 크게 | 800 토큰, 최소 350자 | 문서 4개 각 1청크라 정밀 검색 효과가 작음 | 문서가 길어지면 크기 재조정 |
| 11 | 재색인 | add 반복 / 삭제 후 add | `source` 기준 삭제 후 add | 삭제와 추가 사이 짧은 공백 | 무중단 재색인이 필요해지면 버전 스왑 |
| 12 | 시맨틱 캐시 임계값 | 0.95 / 실측 0.50 | 0.50 (같은 질문 0.63, 교환 0.38) | 샘플이 작아 오적중 가능성 남음 | 실제 질문 로그로 재측정 |
| 13 | 캐시 범위 | 모든 답 / 첫 턴 + 도구 미사용 답만 | 후자 | 적중률 하락 | 사용자별 캐시 키를 두면 개인화 답도 가능 |
| 14 | 캐시 저장소 | 규정 pgvector 재사용 / 분리 | 전용 `SimpleVectorStore` | 재시작 시 소실, 인스턴스 간 공유 안 됨 | Redis 벡터 검색 등으로 |
| 15 | 대화 메모리 | JDBC / 인메모리 윈도우 | `MessageWindowChatMemory` 20개, 인메모리 | 재시작, 수평 확장 시 맥락 소실 | 인스턴스 2개 이상 |
| 16 | 모델 장애 대응 | 실패 그대로 노출 / 재시도 + 폴백 | `@Retryable` 3회 + `@Recover` 폴백 + 안전 문구 | 폴백도 같은 공급사라 공급사 장애엔 무력 | 다른 공급사 키 확보 시 `ChatModel` 두 개로 |
| 17 | 비용 공격(초장문 유도) | 프롬프트로 부탁 / 하드 상한 | `max-tokens: 800` | 긴 답이 필요한 질문도 잘림 | 상담 범위가 넓어질 때 |
| 18 | 응답 방식 | 동기만 / SSE 추가 | 둘 다. SSE는 `token`, `sources`, `done` 이벤트 | SSE 경로엔 캐시와 `toolUsed` 미적용 | 스트림용 도구 추적을 Reactor Context로 옮길 때 |
| 19 | P95 지표 만료 | 기본 2분 / 연장 | 만료 1시간, 버퍼 1 | 최근 변화가 늦게 반영 | 실제 Prometheus + Grafana로 옮기면 서버 쪽 계산으로 |
| 20 | 운영 콘솔 | SPA + WebSocket / 정적 HTML + 폴링 | 정적 HTML, 3초 폴링 | 3초 지연, 반복 요청 | 운영자 다수, 실시간 알림 필요 시 |
| 21 | 설정 | 코드 상수 / 외부화 | `helpdesk.*` `@ConfigurationProperties` record | 설정 파일 이해 필요 | 환경별 값이 갈리면 프로파일로 |
| 22 | 실수 방지 | 리뷰에 의존 / 자동화 | pre-commit(.env, 키 패턴, 5MB, 컴파일), commit-msg, CI 키 스캔 | 커밋이 조금 느려짐 | 팀 규모가 커지면 서버 쪽 브랜치 보호로 |
